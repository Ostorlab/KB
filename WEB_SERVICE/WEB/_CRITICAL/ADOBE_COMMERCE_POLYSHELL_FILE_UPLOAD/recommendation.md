**Upgrade to Magento Open Source / Adobe Commerce 2.4.9 or later, or apply the APSB26-73 backported patch for your supported release line.** The fix first shipped in 2.4.9 final (May 12, 2026) and Adobe backported it to the supported release lines through APSB26-73 on July 14, 2026 — use that bulletin as the authoritative fixed-version list for Commerce, Commerce B2B and I/O Events for Commerce components. Stores on unsupported or end-of-life lines that never received the backport must upgrade; the vulnerable code has been present since the first Magento 2 release, so patch level alone (2.4.8-pN without the backport) is not protection.

While the upgrade is scheduled, apply the interim measures in this order:

1. **Block the attack at the API layer** — deploy a WAF rule that blocks the guest-cart item calls carrying embedded `file_info` uploads (`POST/PUT /V1/guest-carts/*/items*`). This is the only measure that actually prevents the upload; everything below only limits what the uploaded file can do.
2. **Kill execution in the upload directory**:
   * nginx — deny all access to `^/pub/media/custom_options/` with a location block placed **before** any `\.php$` handler (otherwise the PHP handler takes precedence and uploaded shells remain executable);
   * Apache — ensure `pub/media/custom_options/.htaccess` exists with `php_flag engine 0` inside `<IfModule mod_php.c>` and `Deny from all` (rename accordingly if `AccessFileName` is customized).
3. **Treat stores that were exposed as compromised until proven otherwise**: sweep `pub/media/custom_options/` for unexpected files and polyglot images, hunt `accesson.php` backdoors, inspect CMS pages and the `cms_block` table for injected loaders, and check the published Sansec indicators of compromise. Removing an injected script does not remove the database write access the attacker obtained — rotate credentials, API keys and admin accounts, and verify storefront and database integrity.

* Note that the XSS variant applies to all stores before 2.3.5 and to any store whose custom web-server configuration serves `pub/media/custom_options/` as active content, and that the RCE variant depends on the web-server configuration (stock nginx 2.0.0–2.2.x and non-stock nginx passing all `.php` to fastcgi, or Apache before 2.3.5 without `php_flag engine 0`) — verify the actual configuration rather than assuming the default is safe.
