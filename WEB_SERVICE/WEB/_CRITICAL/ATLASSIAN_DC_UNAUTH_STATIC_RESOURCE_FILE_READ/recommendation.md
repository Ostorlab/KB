Upgrade every affected Data Center installation to the first fixed release or later for its line — Bitbucket Data Center 9.4.26 / 10.2.8 / 10.5.1, Confluence Data Center 9.2.26 / 10.2.19, Jira Software Data Center 9.12.40 / 10.3.26 / 11.3.12, Jira Service Management Data Center 5.12.40 / 10.3.26 / 11.3.12, Bamboo Data Center 10.2.24 / 12.1.12, Crowd Data Center 6.3.7 / 7.0.3 / 7.1.7 / 7.2.4, and Crucible and Fisheye 4.9.15. Atlassian no longer ships binary patches; per its bug-fix policy, fixes are backported as maintenance releases on the covered lines. Crucible and Fisheye are end-of-life products that received a final fix — an installation that cannot move past 4.9.15 has no further fix path and should be retired.

* **Patch internet-facing installations first.** CISA listed this weakness in the Known Exploited Vulnerabilities catalog with a due date of October 18, 2026, and requests to the affected endpoints are trivial to script — a single unauthenticated GET is enough.
* **If patching cannot be done immediately, apply Atlassian's interim mitigations**, in order of preference:
  1. A WAF or reverse-proxy rule blocking any URL in which `..` appears immediately adjacent to `/`, `\` or `::`, including URL-encoded and double-encoded forms (Atlassian's advisory carries the exact regex). Test the rule against the encoded variants, not only the literal sequence.
  2. For Confluence, JSM, Jira, Bamboo and Crowd: Tomcat `RewriteValve` rules on `%{REQUEST_PATH}` with a raw-URI `%{REQUEST_URI}` fallback (configuration in the advisory).
  3. For Bitbucket only: a `urlrewrite.xml` rule at the top of the file returning 404 for the same pattern; apply it to all mirror and mirror-farm nodes.
* **Restrict network exposure**: Atlassian recommends removing instances from the internet until patched — including instances that require authentication to use, since this weakness is unauthenticated and pre-authentication.
* **Check for exploitation before closing the finding**: URL-decode access logs (two passes) and search for `..` adjacent to `/`, `\` or `::`, focusing on `download/resources` paths. Successful responses returning `WEB-INF` deployment descriptors are high-confidence indicators; treat any such hit as a data-exposure incident and rotate any credentials, keys or connection strings stored in the files that were reachable under the web application root.
