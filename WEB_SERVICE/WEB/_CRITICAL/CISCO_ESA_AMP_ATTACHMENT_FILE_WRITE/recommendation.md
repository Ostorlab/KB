Upgrade Cisco Secure Email Gateway appliances to a fixed AsyncOS release and let the Content Scanner Tools package update — the two actions together close both the software and the component-level exposure.

* **Upgrade AsyncOS**: the 15.5 line to 15.5.5-014 or later; the 16.5 line to 16.5.0-780 or later; the 16.0 line has **no fixed AsyncOS build** and must migrate to a fixed release. Trains with no in-line fix (13.x, 14.x, 15.0 and 16.0) close the AsyncOS-level exposure only by migrating — Cisco recommends migrating to 16.5.0-780 — while the Content Scanner Tools update below closes the vulnerable component on every licensed and supported release in the meantime.
* **Update the Content Scanner Tools to 25.3.0.5525 or later regardless of AsyncOS release.** The fix is also distributed to all licensed and supported AsyncOS releases through this package update, it does **not** require a software upgrade or a product restart, and devices with automatic updates enabled apply it on their own. To update manually, run `contentscannerupdate` at the CLI; to enable automatic updates, use Security Services > Service Updates > Edit Update Settings > Automatic Updates. Verify the result with `contentscannerstatus`.
* **Verify the configuration condition after patching**: confirm whether File Reputation is enabled and assigned to a mail policy (Mail Policies > Incoming/Outgoing Mail Policies > Advanced Malware Protection). Devices that no longer need the service can disable it as defense in depth; devices that need it are safe once both the AsyncOS fix and Content Scanner Tools 25.3.0.5525+ are in place.
* **If exploitation is suspected**: for physical appliances contact Cisco TAC (remote access enabled speeds the investigation). For virtual appliances, record forensic data **before** rebuilding — upgrading destroys it — then deploy a new VM on a fixed release, rebuild the configuration from scratch without importing previous files, renew all credentials and cryptographic material, and monitor for anomalies. Rebuild every member of a cluster that contained a compromised appliance, since inter-member SSH keys may have been exposed.
* **On Secure Email Cloud**, no action is required: Cisco deployed a fixed Content Scanner Tools version through the standard upgrade process, and customers with observed compromise indicators were contacted directly; those customers should renew credentials and cryptographic material on the appliance.
* **Harden per Cisco's guidance**: keep the appliance off the public internet, separate mail and management interfaces, place appliances behind a filtering device that only admits trusted hosts to management, send logs to an external server, disable HTTP for the admin portal and any unneeded services, use strong authentication (SAML/LDAP) for end users, and change the default administrator password.
* **Monitor for exploitation**: `grep "System Security" system_logs` on every cluster member after the patch window, plus network-side review for unexpected outbound connections from the appliance. There are no workarounds — patching is the only remediation.
