Upgrade every self-managed GitLab CE/EE instance whose version falls inside the affected ranges to a patched release immediately. The vulnerability is unauthenticated, remotely exploitable to arbitrary code execution (CVSS 10.0), and is known to be exploited in the wild.

* **Upgrade to the latest patch release for your track**: GitLab 19.2.8, 19.3.5 or 19.4.2 (or any later release) fix CVE-2026-97229. Review GitLab's upgrade path documentation before upgrading, and note that these patch releases include database migrations: single-node instances will have downtime during the upgrade, while multi-node instances can follow zero-downtime procedures.
* **Fix the bundled Ruby, not just the application**, for source-based or custom deployments: the root cause is an Onigmo integer overflow (ruby/ruby #19020). Upgrade Ruby to 3.4.12, 3.3.13 or a 4.0 release that contains the fixes (4.0.9 contains all of them). Omnibus, CNG and Helm deployments receive the patched Ruby through the GitLab patch releases above.
* **Check the sibling CVEs from the same class** when planning the upgrade: CVE-2026-89078 and CVE-2026-93577 are fixed in GitLab 19.4.1, and CVE-2026-110264 in 19.5.1 — instances that patched only to 19.4.2 may still be affected by CVE-2026-110264 depending on their track.
* **Do not rely on mitigations**: `Regexp.timeout` does not protect against bugs that corrupt memory during pattern compilation, and length limits on patterns are not reliable either — some of these bugs can be triggered by short patterns.
* **If compiling regular expressions from untrusted input is a feature of your own Ruby applications, remove or redesign it.** Compile patterns only from developer-written sources; if a user-supplied pattern must be matched, use a restricted matcher (a literal substring search, a small custom parser, or a regex engine with memory-safety guarantees) instead of passing the input to `Regexp.new`, `Regexp.union` or `Regexp.compile`, or interpolating it into a regexp literal.
* **Review self-managed instances for signs of exploitation** using GitLab's published detections (`Onigmo native worker crash`, `Graphql cilint hostile regexp`, `ci regexp oversized non ascii path`, `ci regexp guard rejection`, `ci lint workhorse worker crash`, `ci lint scripted client error burst`): repeated CI lint worker crashes or regexp guard rejections in a short window warrant incident response, including rotating CI/CD variables, runner tokens, and any secrets the GitLab server can reach.
* **Rotate credentials reachable from the GitLab server** if the instance was exposed and unpatched during the exploitation window — the CI/CD configuration surface gives an attacker access to variables and tokens used by pipelines.
