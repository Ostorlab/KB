Set an enforcing `Cross-Origin-Embedder-Policy` header on top-level document responses, and pair it with the other cross-origin isolation headers.

* **Send `Cross-Origin-Embedder-Policy: require-corp` on document responses.** `require-corp` is the strict option: cross-origin `no-cors` resources are only loaded when they opt in via `Cross-Origin-Resource-Policy` or when they are requested in CORS mode.
  * On resources you control that are meant to be embedded by other origins, send `Cross-Origin-Resource-Policy: cross-origin`; keep `same-origin` or `same-site` for resources only your own origins should embed.
* **Use `credentialless` when third-party embeds do not opt in.** `Cross-Origin-Embedder-Policy: credentialless` allows `no-cors` cross-origin resources to load, at the cost of stripping credentials from those requests — a workable middle ground for pages with legacy third-party images and scripts.
* **Switch embeds that support CORS to CORS mode.** Adding the `crossorigin` attribute to `<img>`, `<script>` and similar elements makes the request a CORS request, which COEP does not block (it is then governed by CORS instead).
* **Enable cross-origin isolation where the site benefits from it.** Pair the COEP header with `Cross-Origin-Opener-Policy: same-origin` on documents; verify with `window.crossOriginIsolated` in the browser console. This also unlocks features that require isolation, such as `SharedArrayBuffer` and unthrottled timers.
* **Roll out in report-only mode first.** Send `Cross-Origin-Embedder-Policy-Report-Only: require-corp` together with `Reporting-Endpoints`, and collect COEP violation reports, to find which embeds would break before enforcing the policy. The `report-to` parameter can be used with the enforcing header as well to keep receiving violation reports after enforcement.
* **Apply the header where it matters**: on HTML document responses (including framed documents), not on every API response — COEP is a document policy.
* **Re-scan** after the change to confirm the header is present and valid (a duplicated or multi-token header is treated as `unsafe-none`, so deploy exactly one valid value), and verify that the site's cross-origin embeds still load.
