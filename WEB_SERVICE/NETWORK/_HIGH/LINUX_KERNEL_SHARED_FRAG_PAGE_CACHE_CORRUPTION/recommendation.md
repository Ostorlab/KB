Update affected kernels to a build that includes the fix (5.15.208, 6.1.174, 6.6.141, 6.12.91, 6.18.33, 7.0.10 or later on the corresponding stable line; for a 5.10.y deployment, the 5.10 backport), or to the fixed kernel package named in the distributor's errata (Red Hat and other vendors have shipped advisories for their streams).

* **On PHP web workloads, patch the whole PHP2Shell chain, not only the kernel.** The observed exploitation chains the unauthenticated PHP RCEs (CVE-2026-109618/CVE-2026-109619) with this bug to reach root; updating the kernel alone leaves the entry point open, and updating PHP alone leaves the root-escalation path open. Treat both as one remediation item for web hosts.
* **Reboot (or otherwise restart) into the fixed kernel**; also plan a restart as part of triage — but be aware that a reboot clears page-cache implants, which can destroy evidence. If compromise is suspected, capture volatile state first (memory, page-cache comparisons, logs) before rebooting.
* **Triage suspected page-cache implants by comparing content read through the page cache against a read that bypasses the cache** (or the underlying block device); on-disk integrity baselines alone will not show this bug's modifications.
* For hosts that must run IPsec/ESP against untrusted peers, prioritize the update on those hosts first — they carry the exposure condition the corruption primitive needs.
